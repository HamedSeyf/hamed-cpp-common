# hamed_common

A header-only C++ utility library intended to be reused as a Git submodule across multiple repositories. It collects common containers, generic helpers, and platform utilities so consuming projects can share and improve these building blocks without copying implementations.

GamePulse is a current consumer. The library also serves as a learning project for modern C++, with an emphasis on C++20 concepts, explicit ownership, generic programming, and synchronization contracts. It is under active development.

## Utilities

| Header | Responsibility |
| --- | --- |
| [`generic_types.h`](include/hamed_common/generic_types.h) | `TRingQueue`, a fixed-capacity ring buffer with emplacement and batch extraction; `TStateMachine`, a generic state-transition base with hooks; and helpers for comparing smart-pointer ownership. |
| [`subscription_registry.h`](include/hamed_common/subscription_registry.h) | `TSubscriptionRegistry<T, K, H>`, a registry with configurable object, key, and handle types. Supports registration, removal, copied query results, early-exit traversal, and predicate-based filtering. |
| [`generic_singleton.h`](include/hamed_common/generic_singleton.h) | `TSingleton<T>`, a helper for lazy access to a function-local static instance, with copying and moving disabled. |
| [`sorts.h`](include/hamed_common/sorts.h) | Comparator-based bubble sort, merge sort, and merging of sorted vectors for algorithm practice and reuse. |
| [`platform.h`](include/hamed_common/platform.h) | Cache-alignment macros, CPU spin-wait hints, a spin-or-sleep helper, and scope-exit cleanup utilities. |

Synchronization belongs at the appropriate boundary: `TRingQueue` requires callers to synchronize concurrent access, while the subscription registry uses shared/exclusive locks internally. Registry traversal and filtering callbacks execute while its locks are held.

## Modern C++ in use

- **C++20 concepts and `requires` expressions/clauses** constrain element types, keys, handles, locks, and callbacks. Removal uses `std::predicate`; traversal accepts a callable with a Boolean-convertible result while allowing stateful callbacks.
- **C++20 `std::span`** exposes batches through views of caller-owned storage.
- **C++20 `std::remove_cvref_t` and `[[no_unique_address]]`** support type normalization and potentially overlapping allocator storage.
- **C++17 `std::optional`, structured bindings, class template argument deduction, and `[[nodiscard]]`** express absent results, simplify generic code, and flag discarded results.
- **RAII, move semantics, perfect forwarding, type traits, and smart pointers** support resource management and explicit type contracts.

## Reuse in another repository

Add this repository as a submodule:

```sh
git submodule add https://github.com/HamedSeyf/hamed-cpp-common.git submodules/hamed_common
```

When cloning a repository that already includes it, initialize its submodules:

```sh
git submodule update --init --recursive
```

In the consuming project's CMake configuration, after defining its application or library target:

```cmake
add_subdirectory(submodules/hamed_common)
target_link_libraries(your_target PRIVATE hamed_common)
```

Replace `your_target` with the consuming target's name. The `hamed_common` interface target provides the include directory and declares a C++20 minimum; there is no separate library binary to link. Headers are available under `hamed_common/`.

## Build requirements and status

The submodule requires CMake 3.23 or newer. Current development uses Windows/MSVC, and several headers use C++20 header-unit imports. The consuming build must support and configure those imports. `sorts.h` also imports a `spdlog` header, so consumers of that header must provide that dependency.

The APIs and portability support are evolving as the utilities are exercised in consuming projects.
